# 前端验修台 · Frontend Replay 产品与验收设计

## 目标

面向使用 DeepSeek Harness 的前端开发者，将真实操作转成可重跑步骤，结合控制台、网络、截图证据验证修复。安装包同时提供 DSH 工具与独立工作台，无需模型 API Key 即可录制和验收。

## 必须交付的完整流程

1. 在工作台创建故障用例，填写目标 URL，启动可见 Chromium，手动操作页面；也支持 Agent 提交结构化步骤。
2. 自动记录顶层页面的点击、输入、选择、勾选、Enter、导航和刷新；采集 console、pageerror、失败请求与 HTTP 错误，以及结束截图。
3. 编辑步骤与验收条件：元素可见/隐藏、文本包含、URL 包含、请求状态、没有页面异常、没有控制台错误、没有失败请求。
4. 以独立浏览器上下文重放。保存不可变的用例快照、逐步骤结果、逐断言结果与截图；不能因步骤通过就宣称验收通过，无断言时标记未验证。
5. 将一次运行显式设为复现基线，修改真实应用后再运行验收，展示断言变化和前后截图。
6. 导出 JSON、Markdown 与独立 Playwright 测试；报告附证据和源码位置候选，不声称已经自动确认根因。
7. 通过实际 DSH 安装包及 Agent 工具调用验证；发布源码、安装包、版本说明和双语 README。

## 实现边界

- 第一版支持 Chromium、顶层 DOM 与 CSS 选择器；跨 iframe、文件上传、拖放和多窗口流程需手动补充，界面与文档明确提示。
- 优先 data-testid、唯一 id 和稳定 CSS 路径；测试运行使用独立上下文，不依赖开发者日常浏览器状态。
- 密码字段不持久化明文，录制时生成显式环境变量占位符；认证流程需要使用者配置相应变量。错误日志中的常见凭据会脱敏。
- 工作台仅绑定本机回环地址。API 使用每次启动生成的令牌和 Origin 校验；不对目标应用开放管理 API，不提供任意文件读取或任意代码执行。
- 并行运行串行化；所有资源通过插件卸载/CLI 退出清理。用例、运行和报告保存在项目 `.dsh-repro/`，不进入安装包。

## 视觉与交互

采用温暖纸白、墨色和信号绿色的工具工作台；左侧用例列表，中间步骤/验收，右侧证据与前后对比。无数据时提供可操作的新建入口和本地演示站点。录制、停止、保存、复现、验收和导出均有明确状态。提供中英文切换、键盘焦点、错误提示、窄屏布局。

## 验证证据

- 单元/接口测试：数据校验、路径边界、脱敏、运行不可变性、API 鉴权、导出。
- 真浏览器：同一示例应用先启用“保存后刷新丢失”缺陷，录制并失败；修复后用完全相同的步骤与断言通过。另测运行错误、无断言、页面异常、网络错误。
- 真 DSH：从 tarball 安装到临时 profile，通过确定性的模型服务调用插件工具，确认实际工具结果进入 Agent 会话。
- 发布：检查 tarball 文件清单，从发布产物安装重跑，验证 GitHub release 和 npm 元数据。发布凭据不足时明确记录阻塞，不把未发布状态称为完成。
